# App Layer Implementation Plan (Plan 2)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the demo app: verifier adapter (real SA re-verification), chain adapter (Arc testnet USDC with simulated fallback), KV persistence, Next.js two-view frontend, Vercel deployment.

**Architecture:** `apps/web` (Next.js App Router) is the assembly point: API routes construct the Pool from a KV snapshot, inject the verifier adapter and chain adapter, execute one operation, persist, respond. Views: financing console (3 buttons drive the demo) + passport page (derived via `@citely-pay/passport`, per-entry re-verification drill-down). Spec: `docs/superpowers/specs/2026-08-02-track2-passport-pivot-design.md` §3, §6, §7.

**Tech Stack:** Next.js 15 App Router, viem (Arc testnet), Upstash Redis KV, `@citely/verifier` via `file:../../../citely-deal-desk/packages/verifier` (sibling clone required — document in README).

## Global Constraints

- Money stays bigint end-to-end; API responses serialize via `encodeSnapshot` conventions (`$bigint` markers) or explicit `.toString()` at the JSON boundary.
- The SA gate lives in the pool (already enforced); the web layer must never pre-filter or bypass rejections — typed rejection codes render verbatim in the console.
- Chain adapter is switchable: `CHAIN_MODE=arc|simulated`; simulated txHashes are prefixed `simulated-` and the UI labels them.
- Secrets only via env vars (`POOL_WALLET_KEY`, `ARC_RPC_URL`, `KV_URL`, `KV_TOKEN`); `.env.example` lists all, no values.
- Every task ends: `pnpm -r test && pnpm typecheck` green before commit.
- Demo release trigger is the console button (no cron).

### Task 1: Verifier adapter + SA fixtures

**Files:** Create `packages/verify-adapter/{package.json,tsconfig.json,src/{index.ts,adapter.ts,fixtures.ts,adapter.test.ts}}` (package layout copied from `packages/passport`; deps: `@citely-pay/pool` workspace, `@citely/verifier` via `file:../../../citely-deal-desk/packages/verifier`, viem).

**Interfaces:**
- Produces `makeSaVerifier(opts: { registeredSigners: readonly `0x${string}`[]; sas: ReadonlyMap<string, SettlementAuthorization> }): SaVerifier` — looks up the SA by `saHash`, runs `checkDeliverableSignature({ sa, registeredSigners })` (+ coverage check when rubric present), maps pass → `{ ok: true, signer, agentId }`, fail → `{ ok: false, reason: <CheckFailure reason> }`, unknown hash → `{ ok: false, reason: "sa_not_found" }`.
- Produces `demoFixtures(): Promise<{ sas: Map<string, SettlementAuthorization>; signers: `0x${string}`[]; badSaHash: string }>` — built with `@citely/verifier/testing` `fixtureSa()`: 3 valid SAs (invoices inv-1..3) + 1 SA signed by an unregistered key (`badSaHash`) for the rejection demo.
- Tests: valid SA verifies ok with signer recovered; tampered/unregistered signer → `ok:false` with machine reason; unknown hash → `sa_not_found`. TDD as in Plan 1.

### Task 2: Chain adapter

**Files:** Create `packages/chain/{package.json,tsconfig.json,src/{index.ts,adapter.ts,adapter.test.ts}}` (deps: viem).

**Interfaces:**
- `interface ChainAdapter { transferUsdc(input: { to: `0x${string}`; amount: bigint; memo: string }): Promise<{ txHash: string }>; explorerUrl(txHash: string): string }`
- `makeSimulatedAdapter(): ChainAdapter` — deterministic `simulated-<counter>-<memo>` hashes; `explorerUrl` returns `#simulated`.
- `makeArcAdapter(opts: { rpcUrl: string; privateKey: `0x${string}`; usdcAddress: `0x${string}` }): ChainAdapter` — viem walletClient ERC-20 transfer, waits 1 confirmation; explorer URL per Arc testnet explorer base.
- `pickAdapter(env: NodeJS.ProcessEnv): ChainAdapter` — `CHAIN_MODE=arc` requires all three vars else throws; default simulated.
- Tests: simulated adapter only (unit); Arc adapter is integration-verified manually in Task 6 (document command in report). Note Arc RPC rate limits — reference deal-desk msb-agent `docs/` for fallback endpoints.

### Task 3: KV-backed pool store

**Files:** Create `apps/web` scaffold (`create-next-app` equivalent checked in manually: package.json with next/react/react-dom, tsconfig extending base with jsx, app/ dir) + `apps/web/lib/store.ts` + `apps/web/lib/store.test.ts` (vitest, no Next runtime needed).

**Interfaces:**
- `interface PoolStore { load(): Promise<Pool>; save(pool: Pool): Promise<void>; withPool<T>(fn: (pool: Pool) => Promise<T> | T): Promise<T> }`
- `makeMemoryStore(boot: (pool: Pool) => void)` — dev/test: singleton in-memory JSON string, same code path as KV (serialize→deserialize every access, so serde bugs surface in dev).
- `makeKvStore(opts: { url: string; token: string; verify: SaVerifier; feeBps: bigint })` — Upstash REST: GET key `pool-state`; absent → new seeded Pool (deposit demo LP 10_000 USDC minor units? use 10_000_000_000n = 10k USDC); optimistic lock via a `pool-version` counter: read version, `SET ... XX` guarded by compare — implement as read-version/write-with-incremented-version, retry once on mismatch.
- `withPool` = load → fn → save. All API routes go through it.

### Task 4: API routes

**Files:** `apps/web/app/api/{escrow,advance,release,repay,passport,state}/route.ts` + shared `apps/web/lib/api.ts` (bigint-safe json helper, error→{code,message} mapping).

**Contracts (all POST unless noted):**
- `/api/escrow` `{invoiceId, amount}` → chain.transferUsdc (importer→pool, demo signer) → `pool.escrowDeposit(+txHash)`.
- `/api/advance` `{advanceId, invoiceId?, saHash, payee, amount, dueAt}` → `pool.requestAdvance(advancedAt: Date.now())`; on ok → `chain.transferUsdc(payee)` → `confirmPayout(txHash)`; on chain failure → `cancelPayout` and return `{code:"CHAIN_FAILED"}`; on rejection → 422 with the typed rejection verbatim.
- `/api/release` `{invoiceId}` → `releaseEscrow(Date.now())`; if residual>0 → transfer → `confirmResidual`; chain failure leaves residual pending, returns `{residualPending:true}` (retry = call again).
- `/api/repay` `{advanceId}` → compute due = principal+fee → simulate buyer payment in → `settleRepayment(Date.now())`.
- `/api/passport?agentId=` (GET) → `buildPassport` from `pool.state()` + `pool.ledger()`; includes per-entry `verifyNow` result by re-running the injected verifier on each saHash (the drill-down anchor) + explorer URLs.
- `/api/state` (GET) → pool.state() summary for the console sidebar (liquidity, pendingPayout, outstanding, feesAccrued, escrows, pendingResidual).
- Tests: route handlers are thin; test `lib/api.ts` bigint json helper + one handler wired with memory store (escrow→advance→release happy path, advance rejection surfaces 422 code).
